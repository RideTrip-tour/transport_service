# Epic 04: Routing Engine

## 1. Цель эпика

Реализовать ядро построения мультимодальных маршрутов по сегментам с поддержкой ограничений и ранжирования.

## 2. Результат эпика

- Модуль построения графа по сегментам.
- Алгоритмы поиска по времени, цене и комбинированной метрике.
- Ограничения пересадок/бюджета/длительности/типов транспорта.
- Возврат `top-N` маршрутов.

Артефакты реализации:
- API контракт: [epic-04-api-contract.md](/home/viktor/PycharmProjects/transport-service/docs/epic-04-api-contract.md)
- Sequence-диаграммы: [epic-04-sequence-diagrams.md](/home/viktor/PycharmProjects/transport-service/docs/epic-04-sequence-diagrams.md)
- README эпика: [epic-04-readme.md](/home/viktor/PycharmProjects/transport-service/docs/epic-04-readme.md)

## 3. Задачи

1. Реализовать модель графа:
   - node = hub;
   - edge = segment.
2. Ввести валидацию сегментов по времени (невозможные пересадки исключать).
3. Реализовать fastest/cheapest/balanced режимы.
4. Добавить параметры ограничений:
   - `min_transfer_minutes`
   - `max_transfers`
   - `budget_limit`
   - `max_total_duration`.
5. Реализовать `top-N` выдачу без комбинаторного взрыва.
6. Добавить guardrails:
   - лимит глубины;
   - лимит числа путей в обработке.
7. Определить и реализовать формат score breakdown в ответе.

## 4. Декомпозиция на подзадачи

1. Выделить этапы `graph build` и `path search`.
2. Отделить фильтрацию допустимых ребер от ранжирования.
3. Подготовить расширение к Pareto-поиску.
4. Реализовать профилирование времени расчета.

## 5. Зависимости

- Вход: Epic 02 (данные), Epic 03 (сегменты от провайдера).
- Выход для эпиков: 5, 7, 8, 9.

## 6. Риски и меры

1. Риск: комбинаторный рост путей.
   - Мера: строгие лимиты и pruning.
2. Риск: некорректные пересадки из-за таймзон.
   - Мера: унификация времени в UTC внутри движка.

## 7. Критерии готовности (DoD)

1. Движок возвращает корректные `top-N` маршруты в рамках ограничений.
2. Алгоритмы детерминированы на одинаковом входе.
3. Есть unit-тесты на сложные графы и edge-cases.

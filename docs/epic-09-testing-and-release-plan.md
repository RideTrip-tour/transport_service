# Epic 09: Тестирование и выпуск

## 1. Цель эпика

Подтвердить корректность функциональности, стабильность под нагрузкой и готовность сервиса к релизу.

## 2. Результат эпика

- Полное тестовое покрытие критичных сценариев.
- CI пайплайн с проверками миграций, unit и integration тестами.
- Проверенный release-процесс и обновленная документация эксплуатации.

## 3. Задачи

1. Реализовать unit-тесты для:
   - routing engine;
   - scoring/ranking;
   - adapter mapping.
2. Реализовать integration-тесты для:
   - `/routes/search`;
   - `/routes/{id}/recalculate`;
   - `/routes/batch-recalculate`.
3. Реализовать контрактные тесты интеграций с провайдерами.
4. Добавить migration tests в CI (`upgrade/downgrade smoke`).
5. Провести нагрузочный smoke для batch.
6. Подготовить release checklist.
7. Обновить `README`, runbook, API примеры.

## 4. Декомпозиция на подзадачи

1. Развести test pyramid: unit > integration > e2e smoke.
2. Подготовить стабильные test fixtures для сегментов и маршрутов.
3. Добавить негативные тесты: 4xx/5xx/timeout внешних сервисов.
4. Формализовать критерии приемки релиза.

## 5. Зависимости

- Вход: все предыдущие эпики.
- Выход: release candidate.

## 6. Риски и меры

1. Риск: неполное покрытие бизнес-ограничений.
   - Мера: таблица трассируемости `требование -> тест`.
2. Риск: flaky-тесты из-за внешних интеграций.
   - Мера: контролируемые моки и contract test doubles.

## 7. Критерии готовности (DoD)

1. CI стабильно зеленый.
2. Все критичные сценарии покрыты автотестами.
3. Release checklist выполнен, документация актуальна.
